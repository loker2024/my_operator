# 正确性验证与性能基准口径

本仓库所有算子统一遵循本文档定义的口径，避免各算子自说自话导致结论不可比。
结论记录在各算子目录 `README.md`（或 `notes/`），本文档只约定"怎么测"。

## 1. 总体原则

1. **先正确，后性能**。每个内核版本必须先通过正确性验证，再做计时。
2. **Release 构建**下计时；数值与规模等参数在算子入口集中配置并写入记录，保证可复现。
3. 同一对比只在**同一台机器、同一构建参数**下进行，跨机器只比数量级。

## 2. 正确性验证

- 输入用固定种子的伪随机数生成（保证可复现），避免极端值掩盖错误。
- 参考实现放在**主机端**，用朴素、易读的循环实现同一算子。
- 输出逐元素比较，判据：

| 算子 | 容差 | 说明 |
| --- | --- | --- |
| Softmax / Attention | 相对误差 ≤ 1e-5（逐元素，跳过 |x| 过小的元素） | fp32 下运算顺序简单，容差从严 |
| GEMM | 相对误差 ≤ 1e-3 | 归约顺序/累加粒度不同，容差放宽 |
| Reduce（行求和等） | 相对误差 ≤ 1e-3 | 长序列 fp32 累加误差随项数增长，累加顺序随归约粒度而变，参照 GEMM 放宽 |

- 逐元素判据示例：

```text
err = |c_gpu - c_ref| / max(|c_ref|, 1e-30)
max_err ≤ tol 且 无 NaN / Inf  →  通过
```

- 失败时打印最大误差位置与前后若干元素，便于定位。

## 3. 性能基准

### 3.1 计时工具

- GPU 计时使用 CUDA event（`common/include/operator_common/GpuTimer.h`），`StopMs` 前隐式同步设备。
- CPU 基线使用 `common/include/operator_common/CpuTimer.h`（`std::chrono::steady_clock`），接口与 GpuTimer 对齐（`Start()/StopMs()`）。
- 内核启动之间不加额外同步，让 GPU 流水线自然衔接（体现真实吞吐）。

### 3.2 迭代策略

- **预热（warmup）**：消除冷启动、驱动初始化、模块加载影响。
- **测量**：连续执行 N 轮内核，各轮独立计时。
- 默认建议：开发阶段预热 1 次、测 100 轮；严格对比阶段预热 1000 次、测 21 组 × 10000 次（组间复位计时）。
- 汇报指标：**中位数**（主指标）、**P5 / P95**（波动区间），不使用平均值（易被离群值带偏）。

### 3.3 指标口径

- 延时型算子（逐元素等）：报告 `ms` 与吞吐（如 `GB/s = 读取字节 / 时间`）。
- 归约 / Softmax：报告**有效带宽** =（输入读取字节 + 输出写回字节）/ 时间。这是"有效"带宽，不代表显存物理带宽，仅用于同算子内不同版本横向对比。
- GEMM：报告 `TFLOPS = 2·M·N·K / 时间`。
- Attention：报告有效带宽（Q/K/V 读 + O 写）为主，同时记录 `ms`。

### 3.4 结果记录模板

```
算子          : softmax         内核版本 : v2_vectorized
形状          : rows=4096, cols=4096 (fp32)
设备          : RTX 4060 Laptop (sm_89), CUDA 12.9
构建          : Release, block=256
预热 / 迭代    : 1000 / 21×10000
中位数        : 0.152 ms     P5/P95: 0.150 / 0.158 ms
有效带宽      : 230.1 GB/s
正确性        : max_err=1.2e-7 (容差 1e-5)  通过
```
