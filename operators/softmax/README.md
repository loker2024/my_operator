# Softmax

对行主序 fp32 矩阵逐行做数值稳定的 softmax：

```text
m_i = max_j x_ij
y_ij = exp(x_ij - m_i) / Σ_j exp(x_ij - m_i)
```

规模关注 `rows × cols`，重点考察全局带宽上限的逼近程度（该算子算力需求低，是典型的**访存受限**算子）。

## 状态

| 阶段 | 版本 | 实现要点 | 状态 |
| --- | --- | --- | --- |
| CUDA | v0 | 每线程处理一行（`row = blockIdx.x * blockDim.x + threadIdx.x`，`grid = ceil(M/block)`），行内串行三遍：求行最大 → 累加 Σexp（max-shift 数值稳定）→ 归一化写回 | 完成（正确性基线，已接入测试） |
| CUDA | v1 | 每行一个 block，行内 `blockDim.x` 个线程以 stride 协同遍历；行最大与 Σexp 各经一次共享内存折半树形归约（读合并、Σexp 累加误差降为树形量级），写回时第三次读行重算 exp | 完成（已接入测试） |
| CUDA | v2 | 每行一个 block，行内遍历同 v1，块内归约改两级 warp shuffle（`warpReduce{Max,Sum}` 先归并每 warp，warp 0 再归约 `num_warps` 个值并广播；寄存器内完成、块内同步降为 ~2 次） | 完成（已接入测试） |
| CUDA | v3 | v2 + `float4` 向量化：列宽为 4 的倍数时行内以 `float4` 读写（行首 16 B 对齐），否则整行回退标量三遍 —— 任意列宽均正确 | 完成（已接入测试） |
| CUDA | v4 | v3 + 整行缓存一遍读：动态共享内存按行宽缓存整行，全局读降为 1 遍、每元素只算 1 次 exp（读+写达理论下限；代价是动态共享内存随行宽增长、占用下降，有上限约束） | 完成（已接入测试） |
| CUDA | v5 | v4 前身思路接入：全局读 2 遍 + float4 —— 动态共享内存只缓存 exp（不再缓存 x），以多读 1 遍全局换掉 v4 的 x smem 写/读往返，exp 仍只算 1 次 | 完成（已接入测试） |
| Triton | t0 | 与 CUDA 同规格的 Triton 实现 | 规划中 |
| Triton | t1 | 与 CUDA 性能对照并记录 | 规划中 |

- 正确性判据：相对误差 ≤ 1e-5（逐元素，跳过 `|ref| < 1e-30` 的元素，见 `docs/benchmark-methodology.md`）。
- 指标：有效带宽 =（输入读 + 输出写）/ 中位耗时，其中输入输出按**逻辑数据量**各计 1 次（每元素 4 B 读 + 4 B 写）。内核实际可能多次读行（v0 每元素读 3 次且访存不合并），低效会直接反映为更低的有效带宽，便于横向比较。

## 版本规划说明

- **v0 每线程处理一行（正确性基线，算法未改动）**：线程线性铺满行号，每个线程独占
  一整行，行内**串行**三遍遍历 —— ① `fmaxf` 求行最大 m；② 以 `expf(x - m)` 累加
  Σexp（max-shift 数值稳定：exp 参数 ≤ 0、行和 ≥ 1）；③ `expf(x - m) / 行和` 归一化
  写回。无 `__syncthreads`、无共享内存，行间完全独立，映射最直观，是正确性基线。
  Σexp 是 fp32 **串行累加**，舍入误差随行宽增长：实测 4096 列时 `max_err ≈ 5.5e-6`
  （仍低于 1e-5 容差但已同量级），行宽更大或更“硬”的输入可能超差，这是 v1/v2
  改用块内分段/树形累加要解决的问题。全局读不合并 + 每元素读行 3 次，实测有效
  带宽仅 ~28 GB/s（远低于显存峰值），属预期，是后续版本优化空间所在。
- **v1 每行一个 block + 共享内存树形归约（当前已实现并接入测试）**：`grid = rows`，
  每 block 处理一行，行内列维由 `blockDim.x` 个线程以 `stride = blockDim.x` 协同
  遍历（warp 同轮访问相邻列 → 全局读合并）。行最大、Σexp 各经一次共享内存折半
  树形归约：Σexp 由 v0 的整行串行累加降为“块内分段 + 树形”累加，fp32 舍入误差
  压到 ~(每线程元素数 + log2(blockDim))·ulp 量级（实测 max_err ~1.2e-6，优于 v0
  同场的 5.5e-6）；写回时第三次读行重算 exp。N 不整除 blockDim.x 时多余线程以
  `-inf` / `0` 空转（归约单位元，不影响结果）。
- **v2 两级 warp shuffle 归约（已实现并接入测试）**：行遍历与归约语义同 v1（三次
  stride 扫行、N 不整除时多余线程以 `-inf` / `0` 空转），仅把共享内存折半树形归约
  换成两级 warp shuffle —— 每 warp 先经 `warpReduce{Max,Sum}`（5 轮
  `__shfl_down_sync`）归为 1 个值，`__syncthreads` 后 warp 0 再归约 `num_warps` 个
  warp 值，并经共享内存广播回全体线程（softmax 的 ②③ 遍需要每个线程都拿到行
  最大 / 行和，区别于 reduce 只需 tid 0 写输出）。归约在寄存器间完成、共享内存只
  做跨 warp 中转，块内同步由 v1 的 ~2×(log2(blockDim)+2) 次降为每趟 2 次。启动
  约束同 v1（`grid = rows`），另要求 `blockDim.x` 为 32 的倍数且 <= 1024（默认
  256）；无动态共享内存。误差量级与 v1 相当（实测 max_err ~1.2e-6），有效带宽
  ~193–198 GB/s，相对 v1 同场 +2~3%，提升来自消减块内同步与共享内存往返。
- **v3 float4 向量化（已实现并接入测试）**：行映射与两级 warp shuffle 归约同 v2，
  行内访问按列宽分派 —— 列宽为 4 的倍数（`row*N` 元素偏移为 4 的倍数 → 行首
  16 B 对齐）时主循环每轮 stride 取 1 个 `float4`（4 列），全局读/写指令数为标量
  的 1/4；否则整行回退 v2 式标量三遍：非 4 倍列宽时第 `row>=1` 行的行首不再
  16 B 对齐，`float4` 重解释是未定义行为，而列宽对整矩阵统一、尾列处理救不了
  跨行对齐（无法逐行选路径）。任意列宽均正确，向量化收益限于对齐宽行。
- **v4 整行缓存一遍读（已实现并接入测试）**：行映射 / 两级 warp shuffle 归约 /
  按列宽分派同 v3，行内遍历改为“整行缓存进共享内存”一遍读完 —— ① 读全局求行
  最大的同时把整行 x 写入动态共享内存（`N * sizeof(float)`，列宽为 4 的倍数时按
  `float4` 槽 16 B 整写）；② 从缓存读 x 重算 exp、原地覆盖为 exp 值并累加行和
  （此后不再重算 exp）；③ 从缓存读 exp 值归一化写回。相对 v0~v3 每元素读行 3
  次、算 2 次 exp，v4 的全局流量 = 读 1 遍 + 写 1 遍、每元素只算 1 次 exp，达
  理论下限。代价是动态共享内存随行宽增长（默认 48 KiB 上限内免 opt-in：场景最大
  列宽 4096 需 16 KiB；更大行宽须 `cudaFuncSetAttribute` 提额）且每 block 占用
  抬升、SM 驻留 block 数下降。实测同场反而低于 v2/v3（见结论记录）：当前瓶颈是
  读行次数外的访存效率与占用，smem 写读往返 + 低占用抵消了少读一遍 / 少算一遍
  exp 的收益，后续优化需换角度评估。
- **v5 全局读 2 遍 + float4（已实现并接入测试）**：v4 前身思路的原样接入 —— 行内
  不再把 x 缓存进 smem：① 全局 float4 读 1 遍求行最大（读后即弃）；② 再全局 float4
  读 1 遍算 exp，把 exp 值 16 B 整写进动态共享内存（`N * sizeof(float)`，只装 exp）
  并累加行和；③ 从 smem 读 exp 乘 inv_sum 后 float4 整写回。相对 v3（全局读 3 遍 +
  exp 算 2 次）全局读降到 2 遍、exp 只算 1 次；相对 v4（全局读 1 遍，但 x 与 exp 各
  一轮 smem 写/读）v5 以“多读 1 遍全局”换掉 v4 对 x 的 smem 往返，smem 流量减半。
  实测见结论记录：宽行 16384×1024 同场 200.23 GB/s 为六版本最高，说明该形状下
  “smem 往返贵过全局重读”；4096×4096 同场 179.40 GB/s 仍低于 v2/v3（~190 GB/s）——
  读 1 遍还是 2 遍（v4 与 v5 仅差 ~1%）不是主因，每 block 整行动态共享内存（16 KiB）
  拉低 SM 驻留数才是，该维度的瓶颈需从占用入手而非再减读行。

## 参考规模

- 默认：`rows=4096, cols=4096`（fp32，约 64 MiB 输入）。
- 可选：`rows=16384, cols=1024`（宽行场景）。
- block 大小默认 256（v0：`grid = ceil(rows/block)`；v1/v2/v3/v4/v5：`grid = rows`，行内由 256 个线程协作；v2/v3/v4/v5 另要求 32 的倍数且 <= 1024；v4/v5 额外要求动态共享内存 `N * sizeof(float)` 不超上限，见状态表与版本规划）。

> 注：`triton/` 与 `notes/` 属规划目录，尚未创建。

测试入口 `src/main.cu` 将 `softmax_v0` ~ `softmax_v5` 注册给同一测试
驱动。因各版行映射与共享内存不同，`main.cu` 以 `RowMap` 描述各内核并按场景推出
启动配置（见 `softmax.cuh` 各版本声明）：v0 每线程处理一行 → `grid = ceil(rows/block)`、
无共享内存；v1 每行一个 block → `grid = rows`、动态共享内存 `blockDim.x * sizeof(float)`；
v2/v3 每行一个 block → `grid = rows`、无动态共享内存（内部仅静态 `__shared__` 中转；
v3 的 `float4` 向量化只影响行内访问，启动配置与 v2 相同）；v4/v5 每行一个 block →
`grid = rows`、动态共享内存 `cols * sizeof(float)`（随列宽增长，`main.cu` 的 `SmemFor`
需按列宽传入 —— v4 缓存整行 x、v5 缓存整行 exp）。
每内核覆盖三类场景：

- **正常流程**：`4096×4096`、`16384×1024`；
- **边界条件**：`1×1`，行数在 block 线程覆盖边界附近的 `(block±1)`、恰满载的
  `block`、末 block 仅余 1 行的 `(2*block-1)`（v0 的关键路径，列宽 3），以及行宽在
  行内协作边界附近的 `3×(block±1)`、恰 1 轮满载的 `3×block`、第 2 轮仅余 1 列的
  `3×(2*block-1)`、warp 边界附近的 `3×(32±1)` / `3×32`（v2/v3/v4/v5 的关键路径
  —— 覆盖
  空转线程、多轮 stride 与整 warp 空转的归约单位元路径；其中非 4 倍列宽场景对
  v3/v4/v5 走标量回退），以及 float4 对齐边界 `3×[4×(block±1)]` / `3×(4×block)` /
  `3×[4×(2*block-1)]`（v3/v4/v5 向量化主循环在 block 线程数附近 —— 空转 / 恰 1 轮
  满载 /
  第 2 轮余 1 个 / 余 `block-1` 个 `float4`，列宽均为 4 的倍数）；
- **异常 / 健壮性**：`0×1024` 空矩阵（越界空转）、`3×0` 空行（遍历 0 次、不写）。

开关（均为 `RunScenarios` 的函数参数，**默认关闭**，在 `main()` 中集中设置）：

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| `enable_boundary` | `false` | 是否执行“边界条件”与“异常 / 健壮性”场景；关闭时每内核只跑正常流程（2 项），开启后全量回归 20 项/内核（6 内核共 120 项） |
| `strict_benchmark` | `false` | 是否按严格口径采样（透传给 `test_softmax_kernel` 的同名参数，与 reduce 测试一致）：关闭时 1 次预热 + 100 次迭代；开启时 1000 次预热 + 21 组 × 10000 次并输出 P5/P95 |

日常开发保持默认即可（只跑有性能意义的大规模形状）；出严格基准数字或做全量
回归时，把 `main()` 中对应常量改为 `true`。

./build/operators/softmax/softmax

## 结论记录

下表为**开发采样**（默认档：1 次预热 + 100 次迭代，`strict_benchmark=false`，
2026-09-09 运行），v0/v1/v2/v3/v4/v5 各数值取自**同一次运行**，横向可比。v0 单次
内核开销 ~4–5 ms，按 reduce 的严格档（21 组 × 10000 次）跑完整张表需数十分钟；
需要时可用开关 `strict_benchmark=true` 逐形状采样后再回填。

口径：正确性相对误差 ≤ 1e-5（GPU vs 主机 double 参考，逐元素）；耗时与有效带宽
按同一次运行的 100 次迭代均值计；有效带宽按**逻辑数据量**（每元素读 1 次 + 写 1 次）。

> 数字说明（v0 之外均读合并 + 行内并行，本次运行同场）：v0 全局读不合并且三遍
> 全由单线程串行（24/30 GB/s），是性能下界。**形状差异明显**：4096×4096 上
> v2/v3 同场 ~190 GB/s 为该形状最高（v1/v4/v5 ~178–180 紧随）；16384×1024 上
> v5 同场 200.23 GB/s 为全表最高，且 v4/v5（179/200）反超 v2/v3（157/177）——
> 宽行场景每行只需缓存 4 KiB，占用约束弱，缓存整行 / 只算 1 次 exp 的收益开始
> 兑现，且“多读 1 遍全局”的 v5 优于“x 走 smem 往返”的 v4（−4.4% vs +11.8% 形状
> 内对比需谨慎，单次采样波动 ~±10%）。整体看，全局读带宽富余、瓶颈在占用与数据
> 复用：4096×4096 的整行 16 KiB 动态共享内存拉低 SM 驻留数，抵消了少读行收益。
> 各版本均低于显存理论峰值 256 GB/s；本次运行相对前次全表整体 ±10% 波动，
> 结论以同场横向对比为准，进一步优化应聚焦占用 / 数据复用粒度。
